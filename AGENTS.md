# Coloring Tracker: архитектура и правила разработки

## Назначение

Это Telegram WebApp и мобильный веб‑трекер раскрасок. Django — источник
истины и административный каталог; Vue 3 — пользовательский интерфейс.
Код из `legacy_kinopub/` является архивом донора и **не импортируется**
активным приложением.

## Активная структура

- `coloring_tracker/` — настройки, URL и Celery-конфигурация Django.
- `app/` — модели трекера, Django admin и JSON API.
- `frontend_webapp/` — Vue 3/Vite интерфейс.
- `tracker_bot/` — минимальный Telegram-бот, открывающий WebApp.
- `Caddyfile` — единая точка reverse proxy для Django, Vite и HMR.
- `tunnel_monitor.py` — получает HTTPS URL Tunnelmole и сохраняет его в
  `data/tunnel_url.txt` для бота.
- `legacy_kinopub/` — только архив; изменения в нём не влияют на продукт.

## Доменная модель

1. `TrackerUser` — пользователь. Основной идентификатор в Telegram —
   `telegram_id`; вне Telegram используется временный `session_key`.
2. `ColoringBook` — книга из каталога. Только персонал Django admin имеет
   право создавать, менять и публиковать книги.
3. `ColoringPage` — одна работа в книге. Обычная страница имеет `number`.
   Разворот — одна запись с `number` и `spread_end`, а не две работы.
4. `UserBook` — книга в личной коллекции пользователя.
5. `ColoringWork` — завершённая работа пользователя, с опциональной
   фотографией и датой завершения.
6. `FavoriteBook` — сохранённая пользователем книга из каталога.

Никогда не используйте кино-термины (`Show`, `ViewUser`, `Wishlist`,
`rating`) для новых сущностей трекера.

## Целостность данных

- Не создавайте каталог книг из пользовательского API. Пользователь может
  только добавить опубликованную книгу в свою коллекцию.
- Номер страницы уникален в рамках книги.
- Диапазоны страниц и разворотов не должны пересекаться. При добавлении
  разворота обязательно указывайте `spread_end > number`.
- Одна страница/разворот может иметь только одну работу в рамках `UserBook`.
- При удалении отметки работы удаляется и её фотография как часть работы.
- Не меняйте `completed_at` при повторной загрузке фотографии: это дата
  завершения, а не дата редактирования.

## Telegram-авторизация

- Фронтенд передаёт `Telegram.WebApp.initData` только в заголовке
  `X-Telegram-Init-Data`.
- Сервер обязан валидировать HMAC Telegram до чтения `user.id`.
- Токен берётся из `TELEGRAM_BOT_TOKEN`; `BOT_TOKEN` поддерживается только
  как временная совместимость с прежним `.env`.
- Нельзя считать `initDataUnsafe.user` достоверным без серверной проверки.
- Гостевая сессия допустима только для локального браузерного тестирования.

## API и интерфейс

- JSON API расположен под `/api/tracker/`.
- Все клиентские запросы должны идти через `frontend_webapp/src/api.js`, чтобы
  Telegram-заголовок не был пропущен.
- После изменения работы, избранного или коллекции обновляйте данные из API,
  не имитируйте состояние только на клиенте.
- Пользовательские тексты — на русском. Сохраняйте компактный mobile-first
  интерфейс и не добавляйте desktop-only действия в нижнюю навигацию.
- Для новых экранов сохраняйте маршруты Vue Router; важные фильтры и поиск
  должны быть отражены в query-параметрах URL.

## Локальная разработка и туннель

Единый локальный запуск всех сервисов (включая локальный туннель и бота):

```bash
docker compose up --build
```

Сервисы `tunnel` (Tunnelmole) и `tunnel-monitor` являются обязательной дев-обвязкой локального окружения и запускаются автоматически по умолчанию.

Цепочка запросов в dev-режиме:

```text
браузер / Telegram → HTTPS Tunnelmole → Caddy :8000
→ Django :8000
→ /__vite__ и /hmr → Vite :5173
```

`proxy` — единственный опубликованный HTTP-порт. Не публикуйте `web` или
`frontend` отдельно без необходимости: это обходит единый маршрут WebApp.
При запуске `tunnel-monitor` отслеживает логи туннелирования, перехватывает публичный HTTPS URL и обновляет `data/tunnel_url.txt`. Бот читает этот файл при выполнении команды `/start`.

Tunnelmole не проксирует WebSocket-upgrade Vite HMR надёжно. Поэтому в Compose
для публичного туннельного URL всегда задавайте `VITE_HMR_ENABLED=false` и не
подключайте `/__vite__/@vite/client`: иначе Telegram WebApp получает `404` на
`/__vite__/hmr` и входит в цикл переподключений и перезагрузок. После изменений
фронтенда в Telegram обновляйте WebApp вручную.

## Конфигурация

- Не коммитьте `.env`, `data/`, `node_modules/` и `dist/`.
- Основа переменных — `.env.example`.
- Переменная `WEBAPP_PUBLIC_URL` используется только как fallback при отсутствии файла `data/tunnel_url.txt`.
- `VITE_DEV_MODE=true` включается Compose для разработки. Production-сборка
  использует Vite manifest и не требует dev server.
- Google Drive backup-файл должен быть создан вручную и заранее расшарен с
  сервисным аккаунтом. Сервисный аккаунт не может создавать этот файл: бэкап
  обязан обновлять ровно один существующий файл с именем
  `GOOGLE_DRIVE_BACKUP_FILENAME`. Эта переменная обязательна и всегда должна
  быть явно задана в `.env`; не добавляйте для неё значение по умолчанию в код.

## Миграции и проверка

- Проект намеренно начинает без исторических миграций. После изменения
  моделей создавайте новую миграцию командой `python manage.py makemigrations app`.
- Перед сдачей запускайте минимум:

```bash
python manage.py check
python manage.py makemigrations --check
docker compose config --quiet
```

- Для изменений Vue дополнительно выполняйте `npm run build` в
  `frontend_webapp/`.

## Визуальный стиль WebApp

- Основная тема интерфейса — лёгкая, женственная и приятная: пудрово-розовая
  палитра с тёплыми кремовыми акцентами, а не холодная синяя или строгая
  «офисная» подача.
- Используйте мягкие градиенты, округлые карточки, деликатные тени и небольшие
  цветочные детали (лепестки, бутоны, цветки) как украшения. Декор не должен
  ухудшать читаемость и нажимаемость на маленьком экране.
- Для пустой обложки книги используйте цветочный плейсхолдер `❀`, а не звезду
  или абстрактную геометрическую иконку. Он должен выглядеть как часть обложки,
  а не как ошибка загрузки.
- Предпочитайте тонкие линейные иконки и понятные цветочные/творческие
  акценты; не перегружайте экран эмодзи и не заменяйте ими функциональные
  иконки навигации.
- Сохраняйте достаточный контраст текста, состояний фокуса и активных кнопок;
  «нежный» стиль не должен снижать доступность интерфейса.
